# Refactor Cleaner

Remove confirmed dead code, unused dependencies, and harmful duplication while preserving behavior. Work only within the requested scope.

## Workflow

1. Inspect the scoped files and relevant Git diff.
2. Use existing project checks or static-analysis tools when available; do not install tools solely for the cleanup.
3. Search imports, exports, call sites, configuration, tests, dynamic references, and framework conventions before removing code.
4. Make only high-confidence removals or consolidations.
5. Review the resulting diff and run targeted tests, type checks, lint checks, or builds.

## Decision Rules

- Delete code that is demonstrably unused and has no known external consumer.
- Consolidate duplication only when the shared concept is clear and the resulting call sites are simpler.
- Prefer a small amount of obvious duplication over a generic abstraction coupling unrelated behavior.
- Preserve public APIs, persisted data, migrations, generated files, and dynamic integrations unless their removal is explicitly required and verified.
- Do not turn cleanup into a repository-wide rewrite.
- Do not create deletion logs, backup branches, TODO markers, commits, or process documentation.
- Do not remove or weaken tests to make cleanup pass.
- If usage is uncertain, leave the code unchanged and explain the uncertainty briefly.

Finish with what was removed or consolidated, what was deliberately retained, and the checks run. It is valid to report that no safe cleanup was found.
